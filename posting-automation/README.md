# 포스팅 자동화

기존 자습실 프로젝트와 독립된 작업 영역입니다. 현재 네이버 계정 접속은 후순위이며, 아래 기능은 외부 계정이나 유료 API 없이 실행합니다.

## 자료 → 원고 → 미리보기

Python 3.11 이상이면 코어 기능은 외부 패키지 없이 실행할 수 있습니다. 기존 Python 가상환경을 사용해도 됩니다. 아래 명령은 posting-automation 폴더에서 실행합니다.

```sh
python -m posting_tool providers
python -m posting_tool prepare source-bundle --root examples --output .local/my-first-preview
```

생성한 `.local/my-first-preview/preview.html`을 브라우저에서 열어 확인하세요. 출력 폴더가 이미 있으면 덮어쓰지 않으므로 다음 실행에는 다른 이름을 지정합니다.

실제 자료는 `resources/inbox/my-article/`에 UTF-8 Markdown/TXT 파일을 읽을 순서대로 넣고 실행합니다.

```sh
python -m posting_tool prepare my-article --title '내 글 제목' --output .local/my-article-v1
```

출력:

- `preview.html`: 확인 필요 항목을 포함한 독립 HTML 미리보기
- `article.md`, `article.html`: 게시용 원고 내보내기
- `article.json`: 원고·템플릿 버전·원본/해시·확인 필요 항목 (내부 기록용)
- `browser-draft.json`: 브라우저 시험 도구가 읽을 수 있는 title/body 계약. 본문은 Markdown 텍스트이며 네이버 서식으로 변환하는 기능은 아직 없습니다. 현재 계정 보호조치로 실제 전달 시험은 보류합니다.

변환은 입력 내용을 번호형 단락에 배치하는 규칙 기반 처리입니다. AI 요약/집필·사실 검증·이미지 수집·자동 업로드는 수행하지 않습니다. 참고 PDF에서 관찰한 번호·단락·출처 구조 중 최소 형식을 구현했으며 원본 블로그의 정확한 디자인 복제는 아닙니다.

현재 렌더러는 제목·문단·목록·구분선만 지원합니다. 입력 HTML과 링크 문법은 문자로 표시하며 실행하지 않습니다. 링크·사진·표를 네이버 서식 그대로 전달하는 기능은 후속 작업입니다. Markdown 내보내기는 원문을 포함하므로 다른 렌더러/플랫폼에 붙이기 전 검토해야 합니다.

## 플랫폼 모듈 확장

`posting_tool/providers/__init__.py`의 `Publisher`를 상속하고 `name`, `capabilities`, 필요하면 `_create_draft()`를 구현합니다. Registry에 인스턴스를 등록하면 원고 처리 코드를 바꾸지 않고 교체할 수 있습니다.

```python
from posting_tool.providers import Publisher, Capability

class MyPlatform(Publisher):
    name = 'my-platform'
    capabilities = frozenset({Capability.EXPORT})
```

실제 업로드를 구현하기 전 `CREATE_DRAFT`를 선언하지 않습니다. 선언하지 않은 기능은 공통 경계에서 거부됩니다. 모의 모듈은 결과에 `simulated=True`를 반환합니다. 서비스/CLI/UI는 플랫폼 조건 분기를 늘리는 대신 이 경계를 사용합니다.

범용 공개 발행은 현재 인터페이스에 없습니다. 이후 필요한 플랫폼의 수정·이미지·상태 조회 등을 별도 capability와 메서드로 확장합니다. 외부 호출의 중복/실패 복구와 리뷰 버전 검증은 영속 서비스 계층에서 구현해야 하며, 현재 reviewed 인자는 영속 승인 시스템을 대신하지 않습니다. 기존 네이버 진단 스크립트는 아직 실제 Publisher 구현으로 이식하지 않았습니다.

## 웹 UI로 사용하기 — 추천

자료 선택부터 편집·미리보기·내보내기까지 브라우저에서 작업할 수 있습니다. WSL의 posting-automation 폴더에서 서버를 한 번 실행합니다.

```sh
bash scripts/run_ui.sh
```

처음에는 전용 .venv-ui와 의존성을 준비합니다. 실행 후 Windows의 평소 브라우저에서 **http://127.0.0.1:8010** 을 여세요. 웹 UI에는 네이버 로그인이 필요하지 않습니다.

1. **예제로 둘러보기**, 또는 Markdown/TXT 파일 선택·끌어 놓기
2. 제목 입력(선택) → **원고 만들기**
3. 원고 수정 → **편집 내용 저장 · 미리보기**
4. 내용·출처 확인 체크 → **본문 복사 / Markdown / HTML / 전체 파일 받기**

편집한 원고는 새 파일 버전으로 `.local/ui/`에 저장합니다. 같은 브라우저 탭 새로고침 시 마지막 원고를 복원합니다. 저장하지 않은 변경은 이탈 시 경고하며 검토 체크는 저장·재접속 시 다시 확인해야 합니다. 원고 목록·제목 검색·이전 버전 열기를 제공하며, 자동 저장과 버전 간 차이 비교는 아직 없습니다. 문서 편집에서 큰 제목·소제목·본문·목록·구분선을 선택하고 이동·삭제할 수 있습니다. 글자별 굵게/색상·사진 편집은 아직 없습니다.

현재 UI는 본인 PC의 loopback 전용 단일 사용자 도구입니다. 로그인/권한 분리 없이 인터넷이나 공유 네트워크에 공개하는 설정은 제공하지 않습니다. 서버 종료는 실행 터미널에서 Ctrl+C입니다. 기존 자습실 UI/서버는 변경하지 않았습니다.

개발 테스트 환경은 `requirements-dev.txt`로 준비하고 `.venv-ui/bin/python -m unittest discover -s tests -v`로 검사합니다. CLI 코어는 계속 Python 표준 라이브러리만으로 실행할 수 있습니다.

웹 UI 상단에는 현재 원고의 단계(자료/편집/검토·내보내기), 저장됨/진행 중/대기 상태와 다음 행동 버튼이 표시됩니다. 편집하면 다시 저장/검토 단계로 돌아갑니다. 파일 받기 클릭은 '전달 요청함'으로 표시하며 다운로드 저장이나 플랫폼 공개를 완료했다고 표시하지 않습니다. 프로젝트 개발 체크리스트는 일반 작업 화면에서 제거하고 TASKS.md에만 유지합니다. 화면에는 사용자의 원고 작성·검토·내보내기·플랫폼 게시 단계를 표시합니다.

[예전 PHP 블로그 연동과 별도 서비스/임베드 검토](docs/INTEGRATION_OPTIONS.md)도 참고하세요.


## 평문 → 문서 편집 → 저장한 원고 → 템플릿 제작

1. **평문 붙여넣기** 탭에 원문을 넣습니다. 빈 줄·번호·글머리표를 규칙으로 정리합니다. AI가 문맥을 추론하거나 새로운 내용을 집필하지 않습니다. 소제목 판정이 맞지 않으면 문서에서 유형을 바꾸세요.
2. 제목과 템플릿을 선택해 **원고 만들기**를 누릅니다. 파일 가져오기 방식도 계속 지원합니다.
3. **문서 편집**에서 문단별 유형·텍스트를 수정하고 ↑/↓/삭제 또는 문단 추가를 사용합니다. Markdown 문법은 필요 없습니다. 고급 사용자는 **Markdown 보기**로 전환할 수 있습니다. 현재 지원하는 제목·목록·문단·구분선 이외의 고급 Markdown은 블록 전환 시 단순화될 수 있습니다.
4. **편집 내용 저장 · 미리보기**로 새 버전을 저장합니다. 하단 **저장한 원고 · 이어쓰기**에서 제목 검색·이어쓰기·이전 버전 열기를 사용합니다. 이전 버전에서 최신 버전을 덮어쓰는 저장은 차단되며, 최신 원고를 다시 열어 수정해야 합니다. 별도 작업이 필요하면 템플릿 적용 사본을 사용할 수 있습니다. 본문 복사는 Markdown 기호 없는 평문으로 전달합니다.
5. **나만의 템플릿 제작**에서 이름·도입·소제목 목록·마무리를 입력합니다. 미리보기는 저장 없이 확인할 수 있고, 저장은 새 버전, 복제는 독립 템플릿으로 생성합니다. 기본 템플릿도 덮어쓰지 않고 새로 저장합니다. 이후 원고 생성 시 템플릿을 선택하거나 **선택한 템플릿으로 사본 만들기**를 사용할 수 있습니다.

사용자 템플릿은 원문을 첫 소제목 아래에 배치하며 다른 소제목은 편집할 수 있는 빈 단락으로 남깁니다. 자료가 의미별로 자동 배분되거나 빈 단락에 사실이 채워지는 기능은 아닙니다. 기존 원고는 템플릿 수정으로 바뀌지 않습니다.

원고 버전은 `.local/ui/<원고버전ID>/`, 템플릿 버전은 `.local/ui/templates/`에 저장합니다. 기존 파일 형식도 읽을 수 있으며 이전 자료를 삭제하지 않습니다. 로컬 단일 프로세스·단일 사용자용이고, 여러 서버 사이의 편집 충돌이나 사용자별 접근 제어는 후속 범위입니다.

## 샘플 템플릿 4종

사이드바 **샘플 4종** 또는 화면의 **같은 이야기, 네 가지 스타일**에서 비교할 수 있습니다.

| 샘플 | 구성 | 디자인 |
| --- | --- | --- |
| 에디토리얼 · 매거진 | 이야기의 시작 → 한 걸음 더 → 생각 남기기 | 종이색·세리프·붉은 강조 |
| 필드노트 · 탐구 일지 | 질문 → 관찰과 확인 → 배운 점 | 초록 노트·점선·부드러운 카드 |
| 스텝가이드 · 실용 매뉴얼 | 준비 → 실행 → 확인/문제 해결 | 파란 단계 카드·자동 번호 |
| 브리핑 · 핵심 요약 | 요점 → 근거 → 다음 행동 | 짙은 남색·노란 강조 |

**크게 보기**는 저장하지 않고 디자인을 확인합니다. **템플릿 선택**은 다음 원고에 사용할 템플릿을 지정합니다. **샘플 원고 열기**는 가상 예제 원고를 저장해 편집할 수 있게 합니다. 기본 템플릿과 마찬가지로 복제·수정해 자기 템플릿으로 저장할 수 있고, 제작 화면에서 디자인 스타일을 바꿀 수 있습니다.

원고는 저장 당시 스타일을 유지합니다. 스타일 포함 HTML(article.html/preview.html)을 내보내지만, 다른 블로그 편집기에 붙여넣었을 때 해당 CSS가 그대로 보존된다는 보장은 없습니다. Markdown·평문은 내용/구성 위주로 전달됩니다. 샘플은 가상의 독서 모임 자료이며 실제 기관의 정보가 아닙니다.


## 즉시 미리보기·처리 상태·디자인 직접 조절

- 템플릿을 선택하면 버튼 없이 선택 영역의 미리보기가 갱신됩니다. 저장/기존 원고 사본 만들기는 별도 동작입니다.
- 제작 화면의 텍스트·스타일·디자인 설정도 잠시 입력을 멈추면 자동 미리보기로 반영됩니다.
- 디자인 직접 조절을 켜면 배경/본문/강조색, 고딕/명조/고정폭, 글자 크기, 줄 간격, 내용 너비, 문단 여백, 소제목 강조를 조절할 수 있습니다. 임의 CSS/코드는 입력하지 않습니다. 설정은 템플릿과 원고 버전에 저장되고 HTML 내보내기에 유지됩니다.
- 원고 생성은 `자료 확인 → 문단·구조 정리 → 템플릿 적용 → 미리보기·파일 저장`의 실제 서버 상태를 보여 줍니다. 근거 없는 진행률 대신 현재 단계·경과 시간·완료/실패를 표시합니다.
- 생성 작업 상태는 .local/ui/jobs에 보관합니다. 같은 탭 새로고침 후 조회를 재개하며 서버 재시작으로 중단된 작업은 재시도 전 저장 목록 확인을 안내합니다. 현재 단일 서버 프로세스에서 한 생성 작업만 처리합니다.
- 복사·다운로드 요청과 외부 플랫폼 게시 완료는 다릅니다. 네이버 자동 게시/로그인은 계속 보류되어 있습니다.

## 자동 개발/테스트 환경과 라즈베리파이

```sh
bash scripts/setup_project.sh --profile dev
bash scripts/setup_project.sh --profile test
# 최초 OS 준비가 필요한 Debian 계열에서만 명시적으로:
bash scripts/setup_project.sh --install-system --profile test
```

같은 의존성 입력이면 재설치를 생략하며 입력 변경 시 고정 버전을 설치합니다. Python 3.11 이상이 필요합니다. `project-environment.json`과 `scripts/project_setup.py`는 다른 Python 프로젝트에도 설정을 바꿔 재사용할 수 있습니다. 기존 자습실/다른 저장소 환경은 건드리지 않습니다.

최초 clone·SSH 터널·이후 fast-forward 갱신 절차는 [라즈베리파이 안내](docs/PI_SETUP.md)를 보세요. 현재 에이전트의 SSH 인증은 거부되어 서버 설치/ARM 실행은 미검증입니다.
