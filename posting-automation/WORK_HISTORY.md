## 로컬 웹 UI 추가

CLI를 일반 사용자에게 요구하기 어렵다는 요청에 따라 FastAPI Controller → Workspace Service → 기존 prepare/export 코어를 연결했다. 별도 프런트엔드 빌드 없이 HTML/CSS/JavaScript View를 추가했다. 자료 선택/드롭·예제·제목·원고 편집·미리보기·검토·복사·다운로드를 제공한다. 편집마다 새 UUID 파일 버전 저장, 같은 탭 새로고침 복원, 미저장 이탈 안내를 구현했다.

실행: bash scripts/run_ui.sh → http://127.0.0.1:8010 . 독립 .venv-ui에서 고정된 의존성 설치와 실행을 확인했다. 네이버 인증과 실제 게시를 사용하지 않았다. UI 요청의 Host/Origin/임의 토큰 및 크기/파일 경로 검사를 추가했다. 원고 내부 HTML은 이스케이프하고 iframe sandbox로 보여준다. 테스트 데이터는 .local/ui에만 저장했다.

브라우저 실검증: 예제 생성→편집→미리보기→검토→ZIP 다운로드, 업로드 파일 생성, 새로고침 복원·검토 초기화, 모바일 가로 넘침 없음. 네트워크 공개·공동 작업·리치 텍스트 편집·원고 목록은 미지원이다.

최종 검증: 독립 .venv-ui에서 단위/API/기존 모의 브라우저 통합 테스트 전체 14개 통과. 최종 UI 브라우저 smoke 검사도 통과했다. HTTP 테스트 클라이언트의 httpx 사용에 대한 Starlette deprecation 안내는 남지만 테스트 실패는 없다. 개발 도구만 requirements-dev에 분리했다. 외부 호스팅은 하지 않았고 QA 서버는 검증 후 종료한다.

## 평문·문서 편집·원고 목록·템플릿 제작 (요청 1~5)

평문 입력/파일 입력 전환과 규칙 기반 빈 줄·번호·글머리표 분석을 추가했다. documents.py가 문서 블록과 제한 Markdown 사이를 변환하고 View는 유형 선택/본문 수정/문단 추가·이동·삭제를 제공한다. 고급 Markdown 보기로 전환할 수 있다. 본문 복사는 Markdown 기호 없는 평문으로 전달한다.

원고는 article_id/parent_id/saved_at를 통해 버전별 파일을 보존하고 최신 목록·제목 검색·이전 버전 열기·이어쓰기를 지원한다. 기존 파일도 기본값으로 읽는다. 같은 프로세스에서 최신 버전보다 오래된 저장은 차단한다. 템플릿은 이름/도입/소제목/마무리의 데이터만 다루며 미리보기는 저장하지 않는다. 저장은 새 버전, 복제는 별도 family, 기존 원고 적용은 별도 사본으로 처리한다. 기본 템플릿과 이미 생성된 원고는 덮어쓰지 않는다. JSON 템플릿은 임시 파일 후 교체해 작성 중 목록 조회에서 깨진 파일을 읽지 않게 한다.

검증: 전체 unittest 19개 통과. check_document_ui.py에서 평문→문서 수정→저장→목록/이전 버전→이어쓰기/새로고침→템플릿 미리보기/저장/수정 버전/복제/사본 적용→모바일을 실제 로컬 Chromium으로 검증했다. 기존 check_ui_browser.py의 파일 업로드·고급 Markdown 편집·검토·다운로드도 통과했다. 화면 캡처로 한글/배치를 확인했다. 첫 브라우저 실행에서는 서버 재시작 전의 이전 경고 문구가 남아 검사 실패했고, 최신 서버 재시작 후 전체 흐름을 재검증해 통과했다.

제한: AI 의미 분석/집필, 자동 문장 요약, 사진/표, 글자별 서식, 자동 저장, 버전 간 차이 비교, 다중 프로세스/다중 사용자 협업은 미구현이다. 사용자 템플릿의 내용은 첫 소제목 아래에 배치하며 나머지 단락은 수동으로 채운다. 임의 템플릿 코드나 HTML은 실행하지 않는다. 네이버 계정/외부 플랫폼은 호출하지 않았으며 공개 배포하지 않았다.

## 즉시 피드백·디자인 조절·자동 환경 구성

사용자는 개발 체크표보다 원고→게시 단계/처리 반응을 원한다고 정정했다. 일반 UI의 개발 체크표를 제거하고 내부 TASKS.md로만 유지한다. Fetch 기반 선택/입력 자동 미리보기, 로딩/경과 시간, 실제 서버 원고 생성 4단계 상태를 추가했다. 단일 생성 작업의 상태는 파일로 남기고 새로고침 조회를 재개하며, 서버 재시작으로 남은 작업은 중단 상태로 전환한다. 다른 처리에 근거 없는 백분율을 사용하지 않는다. 네이버 실제 게시 완료로 표시하지 않는다.

디자인 직접 조절: 배경/본문/강조 색, 고딕/명조/고정폭, 글자 크기/줄 간격/내용 너비/문단 여백/소제목 강조를 허용된 값으로만 입력한다. 임의 CSS는 받지 않는다. 설정은 템플릿/Article 스냅샷과 내보내기에 보존한다.

project-environment.json, setup_project.sh/project_setup.py, update_project.sh를 추가했다. UI/dev/test 프로필, 독립 venv 생성, 의존성 입력 변경 감지, 명시적 OS 설치 옵션, 테스트, dirty 작업 보호와 pull --ff-only를 제공한다. 다른 Python 프로젝트에 manifest와 스크립트를 옮겨 재사용할 수 있다. 다른 저장소·기존 앱 환경은 수정하지 않았다.

검증: 전체 unittest 26개 통과 (로컬 모의 브라우저 포함). 자동 미리보기/실제 작업 단계/로딩/디자인 저장·복원/모바일 및 기존 문서 흐름을 실제 Chromium에서 검증했다. setup 프로필 실행과 동일 입력 재설치 생략을 확인했다. 업데이트 스크립트는 네트워크 없는 임시 Git 저장소로 검증했다.

원격: 사용자가 제공한 라즈서버 정보로 읽기 전용 SSH pwd를 시도했으나 공개키/비밀번호 인증이 거부됐다. 실제 clone/pull/ARM 설치·서비스/도메인 변경은 수행하지 않았다. 최초 clone/설치와 이후 갱신, SSH 터널 안내를 PI_SETUP.md에 남겼다. 실제 ARM 실행은 미검증이다. 다음 사용자 우선순위는 사진·캡션·출처를 포함한 블로그 글 작성이다.

최종 화면 확인에서 처리 완료 안내가 스크롤 중 제작 폼을 가리는 점을 발견해 진행 중에만 sticky로 표시하고, 완료 후에는 일반 흐름으로 돌아가도록 보완했다. GitHub push는 자동 승인 검토가 이번 전체 커밋/대상에 대한 구체적 egress 승인이 부족하다고 판단해 차단했다. 라즈서버 SSH 인증 거부와 별개이며 원격 반영 완료로 기록하지 않는다.
