# 서버 운영 에이전트 지침

## 관리 단위

- 이 파일이 있는 디렉터리가 서버 관리 루트다. 프로젝트는 <루트>/<프로젝트>/에 둔다.
- projects.json과 README.md에서 코드 위치, 운영 정의, 데이터, 백업, 이관 상태를 먼저 확인한다.
- 표준 구조는 프로젝트별 repo/ (Git 코드), data/ (영속 자료), backups/ (로컬 복구본)이다. .env는 서버 전용이며 Git에 넣지 않는다.
- 프로젝트 루트의 compose.yaml을 단일 운영 진입점으로 삼는다. repo 안에 이미 Compose가 있으면 루트 파일에서 지원되는 include/경로 지정 방식으로 재사용하거나 운영 파일 위치를 등록한다. 같은 정의를 복사해 두 군데서 수정하지 않는다. 적용 전 build/mount 경로 기준을 확인한다.
- Compose 프로젝트 이름은 등록한 프로젝트 slug와 일치시키고 명령에도 프로젝트 이름과 파일 경로를 명시한다. container_name, host 포트, 외부 네트워크·볼륨 이름 충돌을 별도로 확인한다.
- 디렉터리 등록은 이관 완료나 실행 성공을 뜻하지 않는다. status=registered_not_migrated는 기존 경로가 실제 운영 위치다. 빈 repo/data에 서비스가 연결됐다고 가정하지 않는다.

## 작업 전

1. AGENTS.md → projects.json → 프로젝트 README.md → MIGRATION.md 순서로 읽는다.
2. 최근 조사와 현재 git/컨테이너/포트/마운트를 대조한다. 오래된 보고서를 실시간 상태로 간주하지 않는다.
3. 한 번에 한 프로젝트만 다룬다. 기존 DuctTape, File Browser, Nginx 및 Tailscale 443/8443의 역할을 보존한다.
4. source 경로를 심볼릭 링크로 바꾸거나 폴더를 먼저 이동하지 않는다. Compose build/mount, systemd, cron, Samba/NFS 의존 경로를 확인한다.

## 변경·이관

- 기본은 계획/진단 모드다. 사용자 요청이 실제 변경을 이미 승인한 범위에서는 불필요하게 재승인을 요구하지 말고 필요한 검증을 수행한다.
- 데이터 이동·서비스 중단은 구체적 영향과 복구 경로를 정한 후 진행한다. 기존 파일은 덮어쓰지 않는다.
- DB 백업은 서비스에 맞는 일관된 방법으로 수행한다. 원고/사진/설정/DB/필요 볼륨을 포함하고 복원 시험한다. backups/ 외에 서버 밖 사본도 유지한다.
- 초기 컨테이너 전환은 기존 데이터 위치를 그대로 연결해도 된다. 기존 data 경로와 최종 경로를 구분해 기록한다.
- 단일 관리 작업이 전체 docker compose down, --remove-orphans, system prune, down -v, 볼륨 삭제를 암묵적으로 수행하면 안 된다.
- Tailscale Serve/Funnel reset이나 기존 루트 매핑 변경을 자동 수행하지 않는다. 포스팅은 tailnet 전용 8443, 기존 DuctTape는 기존 443 연결을 유지한다.
- 앱 설정·코드·백업을 모두 Git pull로 취급하지 않는다. Git 저장소는 repo/ 경계이며 data/backups/.env/logs는 별도다.
- 업데이트는 대상 프로젝트만 빌드/교체한다. 일반 재시작 정책은 unless-stopped, 로그 회전·상태 점검을 설정한다. Docker 데몬 자동 시작과 ARM 호환성을 실제 검증한다.

## 로그·장애 대응

- 작업 시작/종료, 대상, 단계, 에러 코드, 재시도·복구 방법, 로그 경로를 남긴다.
- .env/토큰/비밀번호/개인키/원고 본문/컨테이너 환경변수/전체 inspect/프로세스 인자를 로그로 출력하지 않는다. 진단 stderr도 무조건 복사하지 않는다.
- 오류가 나면 중단하고 실패 단계를 확인한다. 광범위한 삭제/권한 변경/반복 재시작으로 해결하지 않는다.
- 실패 후 재실행할 때 이미 생성한 파일과 기존 서비스 상태를 보존한다. 불완전한 등록/부분 이관은 숨기지 않는다.
- 완료 기록은 변경 대상·검증 결과·남은 미확인·백업/복구 위치를 프로젝트 MIGRATION.md 및 최상위 작업 이력에 기록한다.
- status/doctor 출력은 점검 결과이며 백업·복구·접속 성공을 대신하지 않는다.

## 기존 서비스의 부분 수정

projects.json에 legacy_compose_overrides가 있으면 원본 Compose와 함께 적용해야 한다. 부분 수정으로 생긴 override를 무시해 재생성하지 않는다. File Browser health 수정은 현재 이미지 ID 고정 및 기존 mount 유지가 전제이며 설정/DB/공유 파일은 이관하지 않는다. 별도 이관 검증 전 registered_not_migrated를 완료로 바꾸지 않는다.

## 원격 실행과 불확실한 결과

remote_server.py를 통한 원격 작업은 ~/web-server/remote-runs/<작업ID>/에 결과를 남긴다. 결과가 unknown/running이면 동일 ID의 collect로 조회하고 새 ID로 변경 명령을 즉시 반복하지 않는다. 연결 종료는 원격 실패/취소를 뜻하지 않는다. 인증 실패를 우회하기 위해 비밀번호 저장, sshpass, 호스트키 검증 해제를 도입하지 않는다. 플랫폼의 실행 승인은 별도 경계다.
