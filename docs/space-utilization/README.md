# 공간활용 작업 진입점

갱신: 2026-11-05

다른 AI에게 전달할 시작 경로는 `docs/space-utilization/README.md`다. 저장소 루트 AGENTS.md를 준수하고, 이 작업의 기획·진행 정보는 아래 문서에서 읽는다. 루트의 블로그 기획 및 posting-automation 문서는 공간활용 작업의 선행 자료가 아니다.

## 읽는 순서

1. [PROJECT_PLAN.md](PROJECT_PLAN.md): 확정 범위와 제안 구분
2. [TASKS.md](TASKS.md): 완료·미완료 체크리스트
3. [HANDOFF.md](HANDOFF.md): 현재 상태와 재개 절차
4. [WORK_HISTORY.md](WORK_HISTORY.md): 결정과 검토 이력

엑셀 기반 기획을 이어갈 때는 [EXCEL_ANALYSIS.md](EXCEL_ANALYSIS.md)의 확인 사실·제안·미확정 질문을 함께 읽는다.

## AI 실행 기준

- 먼저 작업 경로, git remote, 현재 브랜치, 미커밋 변경을 확인한다. 사용자 변경을 보존한다.
- 기획 확정 전에는 문서 정리와 읽기 전용 조사를 진행한다. 핵심 요구 충돌은 임의 변경하지 않고 확인한다.
- 구현 시 이 문서 묶음과 실제 코드를 함께 확인한다. 문서의 구현 상태만으로 실행 성공을 가정하지 않는다.
- 진행 안내는 `N / MAX — 단계명` 형식으로 간결하게 작성한다.
- 새 구현 단계는 `feature/<단계>`에서 진행한다. 커밋·develop 병합·push는 별도 사용자 승인 없이 실행하지 않는다. 승인 후 develop 통합 시 --no-ff 기준을 따른다.
- 기존 DB를 열거나 앱을 실행하기 전에 DB 경로와 초기화 동작을 확인한다. 실제 데이터 변경·전환은 별도 확인한다.
- 사용자 자료·인증정보·.env·실제 DB를 새로 Git에 추가하지 않는다.
- 검증은 변경 대상에 맞춰 수행한다. 포스팅 테스트를 공간활용 기능 검증으로 대신하지 않는다. 구현·정적 검토·모의 테스트·실행 검증을 구분해 기록한다.
- 작업 후 TASKS, HANDOFF, WORK_HISTORY를 갱신한다. 확정되지 않은 후보를 완료 요구사항처럼 기록하지 않는다.
