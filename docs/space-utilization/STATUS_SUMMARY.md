# 공간활용: 기존 기획과 구현 현황

작성: 2026-11-20 · 대상: 후속 검토자(Claude 등) · 근거: 이 폴더 문서, `backend/`, `frontend/`, Git 이력. 실제 DB 내용은 읽지 않았다. 아래 구현은 별도 명시가 없으면 소스 정적 검토 결과이며 실제 동작 확인을 뜻하지 않는다.

## 1. 확정된 요구와 목적

- 자습실·작업실 등 공간활용 업무에 집중하고, 기기 초기화·프로그램 설치·기기 상태 관리는 제외한다. 상세 기능과 첫 버전 범위는 아직 확정되지 않았다. ([PROJECT_PLAN.md](PROJECT_PLAN.md))
- 수기·엑셀 업무를 프로그램으로 확장해 다른 사람의 편집으로 수식이 훼손되는 문제를 줄인다. 고정된 좌석번호를 사용하는 가운데 이용자는 이동하고 좌석도 추가·제거할 수 있어야 한다.
- 기존 양식은 동료 교사에게 전달한 사용 양식이며 실제 참/불참 결과를 기록한 파일이 아니다. 빈칸은 미응답일 수 있다. 실제 출결과 사전 조사 상태를 단정해선 안 된다. ([EXCEL_ANALYSIS.md](EXCEL_ANALYSIS.md))
- 공간 공통 구조와 자습실·작업실 옵션, 좌석 관리 옵션 및 첫 버전 기능은 제안·검토 중이다. 예약이나 대여의 구체적 정책은 확정된 요구로 기록되어 있지 않다.

## 2. 엑셀에서 가져온 업무와 확장 방향

| 구분 | 확인된 내용 또는 제안 |
| --- | --- |
| 엑셀 구조 | 좌석번호·학번·이름·성별·자습실, 월~목 4개 시간대의 불참 사유 조사, 일반실·정독실 출석부와 좌석표, 감독교사 배정 설명. 출석부는 FILTER/LET, 좌석표는 공간과 좌석번호로 XLOOKUP한다. |
| 확인 범위 | 기존 문서의 XLSX 구조 분석 결과다. Excel 화면 실행·수식 재계산·외부 연결 갱신은 하지 않았고, 업무 순서는 가설이다. 원본을 이번에 다시 열지 않았다. |
| 확장 제안 | 공간·기간·시간대·이용자·좌석·기간별 배정·반복 불참과 날짜 예외를 분리하고, 같은 데이터로 운영표·좌석표를 생성한다. 입력과 계산 규칙을 분리하고 이력·백업을 검토한다. |
| 후속 후보 | XLSX 가져오기·출력, 실제 출결, 담당자 배정 자동화, 작업실·팀·시간 예약은 제안 또는 결정 대기다. 이미 구현된 기능이나 승인된 범위가 아니다. |

상세 근거와 추론의 구분은 [EXCEL_ANALYSIS.md](EXCEL_ANALYSIS.md), 확정과 권고의 구분은 [PROJECT_PLAN.md](PROJECT_PLAN.md)를 참조한다.

## 3. 실제 구현된 기능 — 소스 기준

- [backend/main.py](../../backend/main.py): FastAPI 루트·상태 응답, 학생 전체 조회(`GET /students`)와 등록(`POST /students`). 이름·학번 공백, 성별 남/여, 방 구분 정독/일반을 검증하고 전체 학생을 대상으로 좌석번호 중복을 검사한다.
- [backend/app/models/student.py](../../backend/app/models/student.py): 학생 ID와 좌석번호·학번·이름·성별·방 구분을 단일 `students` 테이블에 저장하는 모델. 별도의 공간·좌석·배정 모델은 없다.
- [backend/app/database/db.py](../../backend/app/database/db.py): 실행 작업 디렉터리 기준 `study_room.db` SQLite 연결과 세션. `main.py`를 불러오면 테이블 생성이 시도된다.
- [frontend/src/App.jsx](../../frontend/src/App.jsx): 학생 입력 폼과 전체 목록, 등록 후 목록 갱신. API 주소는 `http://localhost:8000`으로 고정되어 있다.
- [backend/scripts/generate_dummy.py](../../backend/scripts/generate_dummy.py): 합성 학생 생성 코드가 있으나 실행 시 연결된 DB의 기존 학생을 모두 삭제한다. 이번에는 실행하지 않았다.
- 이력상 `8634451`은 기본 연동, `51891b2`는 스키마·더미 스크립트, `2433d9a`/`5066702`는 폼·목록, `9168c77`은 입력 검증을 기록한다. `62b2834`는 이후 엑셀 기반 기획 문서다. 과거 커밋 제목은 이번 실행 검증이 아니다.

## 4. 미구현·미검증

- 독립 공간·좌석 관리, 이동 및 배정 이력, 수정·삭제 UI/API, 운영 기간·시간대, 불참 조사·예외, 출결, 운영표·좌석표, 감독 배정, 대여/예약, XLSX 입출력은 현재 살펴본 코드에 구현되어 있지 않다.
- 인증·권한, 변경 이력, 백업·복구, DB 수준의 좌석 중복 제약 및 동시 요청 안전성은 확인되지 않았다. 좌석번호 범위나 학번 중복 검증도 코드에 없다.
- 이번에는 API 서버·브라우저·등록/조회·DB·엑셀 실행을 검증하지 않았다. 의존성 전체 설치 상태와 실제 운영 환경도 확인하지 않았다.

## 5. 기획과 구현의 차이

- 엑셀 좌석표는 공간과 좌석번호를 함께 조회하지만 API는 공간 구분 없이 번호 전체 중복을 막는다. 공간 간 동일 번호 허용 여부 자체는 미결정이다.
- 좌석 식별과 이용자 이동·좌석 추가/제거 요구에 비해 현재는 학생 레코드에 번호가 붙어 있고 변경·이력 기능이 없다. 공간별 좌석 옵션은 아직 설계 제안이다.
- 엑셀의 반복 불참·공간별 표·감독 배정과 수식 훼손 방지를 위한 운영 흐름은 현재 학생 등록·목록만으로 재현되지 않는다.
- 범용 공간활용 방향은 검토 중인 반면 현 모델은 학번·성별·정독/일반을 필수로 고정한다. 공통 모델 채택 및 기존 데이터 전환은 미결정이다.
- 프런트엔드는 HTTP 오류 상태를 확인하지 않고 응답을 JSON으로 읽은 뒤 폼을 초기화하므로 등록 실패가 사용자에게 제대로 전달되지 않을 수 있다.

## 6. 남은 결정 — 객관식 후보

각 문항은 논의용이며 복수 선택 또는 다른 답변이 가능하다.

1. 첫 범위: A 자습실 엑셀 업무 재현 B 공통 공간관리부터 C 대여/예약부터.
2. 좌석 관리: A 공간별 선택 기능 B 모든 공간 필수 C 우선 자습실만 지원.
3. 공간 간 좌석번호: A 중복 허용 B 전체 고유 C 공간 유형별 설정.
4. 이동·좌석 제거: A 배정 종료와 이력 보존·좌석 사용 중지 B 현재 상태만 수정 C 다른 정책.
5. 일정·출결: A 주간 반복 불참만 B 날짜 예외 포함 C 실제 출결까지 포함. 빈칸은 미확정으로 보존하는 정책도 확정 필요.
6. 첫 운영 산출물: A 운영표·좌석표 출력 B 감독 배정 포함 C XLSX 가져오기 포함. 필요한 조합과 우선순위 선택.
7. 운영 권한·데이터: A 담당자만 입력 B 이용자도 제출 C 역할별 권한; 기존 DB 보존·전환과 백업 방식도 함께 결정.

## 7. 실행·테스트 방법과 이번 확인 결과

- **확인:** 저장소 루트에서 `npm --prefix frontend run lint`를 실행했고 종료 코드 0이었다. 이는 정적 검사 통과이며 브라우저나 API 동작을 보증하지 않는다.
- **미실행 안내:** 별도 격리 작업 디렉터리에서 백엔드 의존성을 설치한 후 `PYTHONPATH=/절대경로/backend uvicorn main:app --host 127.0.0.1 --port 8000`으로 시작할 수 있다. 작업 디렉터리에 `study_room.db`가 생성·변경될 수 있으므로 실제 DB가 없는 격리 디렉터리를 사용한다. 기존 DB와 데이터에 대한 실행 승인은 이번 요청에 없다.
- **미실행 안내:** 프런트엔드는 `cd frontend && npm install && npm run dev`로 개발 서버를 시작할 수 있다. API와 브라우저를 연결한 실행 결과는 확인하지 않았다. `npm run build`도 실행하지 않았다.
- 공간활용 전용 자동 테스트는 조사한 파일 목록에서 발견하지 못했다. 더미 생성 스크립트는 기존 학생을 삭제하므로 실제 DB에 실행하지 않는다.

Git이 추적하는 `backend/study_room.db`에 개인정보가 들어 있다면 저장소와 이력을 통한 노출 위험이 있다. 내용은 확인하지 않았다.
