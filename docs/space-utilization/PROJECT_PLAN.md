# 공간활용 기획

갱신: 2026-11-05 · 상태: 방향 제안 정리, 상세 기획 미확정

## 사용자 확정 사항

- 현재 대화는 자습실·작업실 등 공간활용에 집중한다.
- 작업별로 문서를 분리해 다른 AI가 해당 작업의 문서를 선택해 읽을 수 있게 한다.
- 기기 초기화, Office 등 프로그램 설치, 기기 상태 관리는 다른 저장소의 범위로 제외한다.
- 기존 내용과 요청이 충돌하면 확인한다. 기획 확정 후 구현한다.
- 커밋 및 push는 별도 승인 후 진행한다.

## 엑셀 기반 후속 기획

가칭은 `space-utilization`이다. 사용자 지정 엑셀을 읽기 전용 분석했으며 [분석과 확장 기획](EXCEL_ANALYSIS.md)에 근거와 단계안을 기록했다. 반복 불참 일정·공간별 운영표·좌석표·감독 배정이 확인되어 운영 기간·시간대·이용 예외를 공통 구조 후보에 추가한다. 상세 정책과 첫 구현 범위는 사용자 확인 전이다.

## 제안 중인 구조

사용자는 공간활용 프레임워크에 자습실·작업실 기능을 옵션으로 추가하는 방향에 대한 의견을 요청했다. 아래는 AI 제안이며 구현 승인이나 상세 요구 확정을 의미하지 않는다.

공간 명칭보다 이용 방식에 따라 기능을 구성한다. 초기에는 범용 플러그인 엔진 대신 공통 데이터 구조와 선택 기능으로 시작한다.

| 구성 | 공통 모델 후보 | 용도별 옵션 후보 |
| --- | --- | --- |
| 공간 | 명칭·위치·정원·운영시간 | 정숙 구역·공동 작업 구역 |
| 이용 단위 | 좌석·방·작업대 | 지정석·공용 작업대 |
| 이용자 | 이용자 정보·이용 권한 | 학생 정보·팀 정보 |
| 이용 기록 | 배정·이용 시작·종료·상태 | 출결·작업 시간 |
| 정책 | 이용 가능 시간·중복 제한 | 정기 배정·시간 예약 |

자습실·작업실은 기본 설정 묶음으로 제공하고 표시 명칭을 바꿀 수 있게 하는 방안을 제안한다. 같은 공간의 시간별 용도 변경은 설계 검토 후보이며 초기 지원을 확정하지 않는다.

## 첫 구현 제안 및 결정할 사항

공간 → 이용 단위 → 이용자 → 배정·이용 기록 흐름을 만들고 기존 자습실을 첫 검증 사례로 사용하는 방안을 제안한다.

- 공통 뼈대와 첫 검증 사례를 위 제안대로 채택할지 확정한다.
- 첫 버전에 배정만 포함할지, 이용 시작·종료까지 포함할지 결정한다.
- 예약·출결·팀 이용의 우선순위를 결정한다. 현재는 모두 후보이다.
- 학생·학번·성별·정독/일반 정보를 공통 필수값으로 강제하지 않는 설계를 검토한다. 기존 필드 삭제 및 데이터 전환은 확정하지 않는다.

## 기존 구현과 한계

2026-11-05 소스 정적 검토 기준:

- backend/main.py: FastAPI 학생 목록·등록, 좌석번호 중복 검사, 이름/학번 및 성별·자습실 구분 검증.
- backend/app/models/student.py: 학생과 좌석을 하나의 테이블에 저장한다. 독립 공간·이용 기록 모델은 없다.
- frontend/src/App.jsx: React 학생 입력·목록 화면, localhost:8000 API 주소 사용.
- backend/app/database/db.py: 실행 작업 경로 기준 study_room.db 사용. main.py를 import하면 create_all이 호출된다.
- 중복 좌석 검사는 전체 학생 대상이다. 공간별 구분과 DB 동시성 제약은 별도 검토가 필요하다.
- 실행·브라우저·DB 데이터 검증은 이번 작업에서 수행하지 않았다. DB와 기존 코드는 변경하지 않았다.

## 작업 경계

backend/와 frontend/는 기존 공간활용 구현의 검토 대상이다. posting-automation/과 루트 블로그 기획은 별도 작업으로 유지하며 이 작업에서 수정하거나 서버 운영을 실행하지 않는다. 실제 DB 내용이나 개인정보를 문서에 옮기지 않는다.

## 사용자 운영 설명 반영 — 2026-11-05

### 확인된 사실과 목적

- 기존 엑셀은 다른 교사에게 사용 방법을 전달한 양식이기도 하며, 해당 파일에 참/불참 결과를 실제 기록하지는 않았다. 빈칸은 미응답일 수도 있어 참여 예정으로 해석할 수 없다.
- 기존 업무는 수기와 엑셀로 관리했다. 다른 사람이 수정해 수식이 훼손되면 사용할 수 없게 되는 문제를 방지하는 것이 프로그램화의 주요 계기다.
- 좌석번호는 고정으로 두되 이용자가 이동할 수 있고, 좌석 자체의 추가·제거도 발생한다. 좌석 관리의 옵션화는 사용자 검토 중이다.
- 반복 불참 일정의 적용 기간·반복 정책과 실제 출결 입력 방식은 아직 확정하지 않았다.

### 설계 권고 — 상세 구현 전 검토

좌석 관리는 공간별 선택 기능으로 제공하는 방안을 권한다. 좌석을 쓰는 공간에서는 좌석 식별과 이용자 배정을 분리하고, 좌석을 쓰지 않는 공간에서는 공간·정원 단위로 운영한다. 임의의 좌석을 강제로 생성하지 않는다.

- 공간별 운영 방식 후보: 좌석 단위 / 정원 단위. 예약 기능은 별도 옵션으로 두며 좌석 사용 여부와 혼합하지 않는다.
- 좌석은 내부 ID와 표시 번호를 분리한다. 같은 공간 안에서 활성 좌석 표시 번호가 겹치지 않도록 하되 공간 간 번호 정책은 확인한다.
- 사람의 이동은 좌석번호 변경이 아니라 이전 배정 종료와 새 배정 생성으로 기록한다. 배정 유효 기간을 두어 과거 좌석표를 보존한다.
- 좌석 추가는 새 이용 단위 등록, 제거는 사용 중지로 처리하는 방안을 제안한다. 배정 이력이 있는 좌석을 삭제해 과거 기록을 잃지 않도록 한다.
- 배정 중인 좌석 사용 중지와 좌석 관리 방식 전환은 영향 미리보기와 배정 정리를 거치게 한다. 자동 재배정은 기본 동작으로 넣지 않는다.
- 미응답/미확정, 참여 예정, 불참 예정, 실제 출결 미확인을 구분한다. 기존 빈칸을 참여 또는 결석으로 자동 변환하지 않는다.

수식 보호는 단순히 셀 편집을 막는 기능이 아니다. 입력 데이터와 계산 규칙을 분리하고, 담당자는 검증된 입력 화면에서 값을 수정하며 출석부·좌석표는 동일한 원본 데이터로 생성하도록 한다. 설정 변경과 운영 입력의 구분, 저장 전 검증, 변경 이력, 백업·복구, 규칙 변경에 대한 테스트를 첫 버전 설계에 포함하는 것을 권한다. 구체적인 사용자 역할·로그인 방식은 미정이다.

### 첫 버전 우선순위 제안

1. 공간·운영 기간·시간대 설정과 이용자 등록.
2. 공간별 좌석 사용 여부, 좌석 추가/사용 중지, 이동 이력과 중복 배정 방지.
3. 미확정 상태를 보존하는 일정 입력과 공간별 운영표·좌석표 생성.
4. 담당자용 입력·출력 흐름, 변경 이력·백업 복구 검증.

실제 출결의 프로그램 입력, XLSX 가져오기, 담당자 배정의 자동화 범위는 추가 확인 후 포함 여부를 결정한다. 이 항목은 사용자 설명에 대한 설계 권고이며 전체 기능 구현 승인을 의미하지 않는다.
