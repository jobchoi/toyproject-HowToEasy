# 공간활용 첫 버전 범위

작성: 2026-11-20 · 상태: 2026-11-20 사용자 결정으로 첫 버전 범위 확정. 구현 승인이 아니다.

## 1. 확정 요구

- 여러 담당자가 사용해도 수식 훼손으로 운영이 중단되지 않도록 입력 데이터와 계산 규칙을 분리한다.
- 엑셀 빈칸은 미응답이며 참여로 간주하지 않는다. 사전 응답과 실제 출결은 다르다.
- 좌석번호는 고정하고 이용자는 이동할 수 있다. 좌석 추가와 사용 중지를 지원하고 배정 이력을 보존한다.
- 공통 공간 구조를 기반으로 자습실·작업실 기능을 선택해 추가한다. 좌석 없는 공간은 공간 단위 배정을 지원한다.
- 포스팅 자동화, 기기 초기화·설치·상태 관리는 제외한다.

## 2. 첫 버전 범위

**포함:** 공간 및 운영 기간·시간대 설정, 이용자 등록, 좌석 추가·사용 중지, 기간별 공간·좌석 배정과 이동 이력, 사전 응답 입력 및 공간별 운영표·좌석표 조회. 공통 구조에 자습실 기능을 선택적으로 적용하고 작업실은 공통 공간으로 표현한다. 좌석 없는 공간은 좌석을 생성하지 않고 공간 단위로 배정한다. 담당자는 검증된 화면에서 입력하고 표는 같은 저장 데이터와 고정된 계산 규칙으로 생성한다.

**제외:** 실제 출결 입력, 날짜별 일정 예외, 예약·대여·팀 기능, 감독 배정 자동화, XLSX 가져오기·양방향 동기화, 범용 플러그인 엔진, 자동 좌석 재배정. 표는 화면 조회와 브라우저 인쇄를 지원하며 XLSX 출력은 제외한다. 담당자별 로그인과 역할 구분 없는 입력, 운영자 백업·복구를 지원한다. 사전 응답은 선택한 운영 기간의 요일·시간대에 주간 반복 적용한다.

## 3. 데이터 모델 초안

| 대상 | V1 속성·관계 |
| --- | --- |
| 공간 | ID, 이름, 좌석 사용 여부, 선택 기능; 운영 기간과 시간대는 공간에 연결된 설정으로 관리 |
| 좌석 | ID, 공간, 고정 표시 번호, 사용 상태; 사용 중지해도 이력 보존 |
| 이용자 | ID, 이름과 선택적 식별 정보; 학생 전용 속성은 공통 필수가 아님 |
| 배정 이력 | 이용자, 공간, 선택적 좌석, 시작·종료 시점; 이동 시 기존 배정을 종료하고 새 배정을 생성 |
| 사전 일정 응답 | 이용자, 운영 기간, 요일·시간대, 미응답/참여 예정/불참 예정 및 선택적 사유; 실제 출결 레코드는 V1 제외 |

좌석번호는 공간별로 고유하며 공간 간 같은 번호를 허용한다. 사용 중지된 좌석의 번호도 해당 공간에서 고유하게 유지한다. 같은 시점에 한 좌석과 한 이용자에 중복 활성 배정이 생기지 않도록 저장 시 검증한다. 배정 중인 좌석은 담당자가 배정을 먼저 종료하거나 이동한 후 사용 중지하며 자동 재배정하지 않는다. 기간 경계와 동시 저장 제약은 구현 설계에서 명시한다.

기존 `students` 모델은 학생 정보와 좌석번호·방 구분을 한 행에 결합한다. 신규 공통 이용자와 공간·좌석·배정으로 분리하되 학번·성별 등 기존 필드는 학생용 선택 속성으로 보존하는 방안을 제안한다. 기존 DB 내용은 조사하지 않았으므로 실제 상태를 가정하지 않는다. 전환은 별도 승인 후 백업과 복구 검증, 격리된 복사본에서 매핑·중복/결측 검토와 모의 전환, 결과 검증을 거쳐 진행한다. 원본을 덮어쓰거나 기존 값을 임의 삭제하지 않는다. 기존 방 구분과 좌석번호의 매핑 및 충돌 처리도 전환 전에 확인한다.

## 4. 화면과 흐름

1. 운영 설정: 운영 기간·시간대, 공간 및 선택 기능 설정.
2. 이용자 관리: 이용자 등록·조회·수정 및 학생 선택 정보 입력.
3. 좌석·배정: 좌석 추가·사용 중지, 이용자 배정·이동 및 이력 조회.
4. 사전 응답: 기간·요일·시간대별 응답 입력과 미응답 확인.
5. 운영표·좌석표: 공간과 기간을 선택해 동일한 데이터로 조회; 브라우저 인쇄를 지원한다.
6. 관리: 담당자별 로그인과 역할 구분 없는 입력, 운영자 백업·복구를 제공한다.

## 5. 완료 조건

- 담당자 두 명이 각각 입력 화면에서 유효한 값을 저장하고 다시 조회할 수 있으며 일반 입력으로 계산 규칙을 편집할 수 없다.
- 응답하지 않은 칸은 미응답으로 표시되고 참여 예정·불참 예정·실제 출결로 집계되지 않는다.
- 같은 공간에 좌석번호를 중복 등록하거나 겹치는 기간에 좌석 또는 이용자를 중복 배정하면 저장이 거부되고 이유가 표시된다.
- 이용자 이동 후 이전과 새 배정의 기간·좌석을 조회할 수 있고 과거 좌석표는 해당 시점의 배정을 표시한다.
- 좌석을 추가할 수 있고 배정 종료 후 사용 중지해도 이전 배정 이력이 조회된다. 배정 중 사용 중지는 안내와 함께 거부된다.
- 운영표와 좌석표는 같은 저장 데이터를 사용하며 입력 수정 후 재조회에 반영된다. 공간·기간 필터가 적용된다.
- 좌석 없는 공간에서 좌석 생성 없이 공간 단위 배정과 조회가 가능하다.
- 사전 응답은 선택한 운영 기간 동안 해당 요일·시간대에 주간 반복되고 날짜별 예외는 지원하지 않는다.
- 담당자별로 로그인해 역할 구분 없이 입력할 수 있고 운영자가 백업·복구할 수 있다. 운영표와 좌석표를 브라우저에서 인쇄할 수 있다.
- 합성 데이터로 위 조건과 저장 검증을 자동 테스트하고 주요 화면 흐름을 실행 검증한다. 설계된 백업·복구 방식으로 격리 환경에서 복구 결과를 확인한다.

## 6. 확정 결정

2026-11-20 사용자가 다섯 추천안을 모두 확정했다. 추후 운영하며 보완 시 갱신한다.

| 항목 | 확정 내용 |
| --- | --- |
| 좌석 없는 공간 | 좌석 생성 없이 공간 단위 배정 지원 |
| 사전 일정 | 운영 기간 동안 요일·시간대별 주간 반복; 빈칸은 미응답 |
| 표 활용 | 화면 조회와 브라우저 인쇄 |
| 담당자 접근·복구 | 담당자별 로그인, 역할 구분 없이 입력, 운영자 백업·복구 |
| 좌석번호 범위 | 공간별 고유, 공간 간 중복 허용 |

구체적 인증 및 복구 절차는 운영 환경 확인 후 설계한다.

## 7. 구현 작업 순서

1. 운영 환경과 기존 데이터 전환 승인 여부를 확인한다.
2. feature 브랜치에서 공통 모델, 기간·시간대, 선택 기능과 저장 제약을 설계한다.
3. 공간·이용자·좌석·배정 이력 및 이동 흐름을 구현하고 합성 데이터로 검증한다.
4. 사전 응답과 운영표·좌석표를 구현하고 미응답·기간 경계·동시 배정을 검증한다.
5. 확정된 접근·출력·백업 복구 흐름을 구현하고 격리 환경에서 주요 화면과 복구를 검증한다.
6. 전환이 별도 승인된 경우에만 복사본에서 모의 전환과 검증을 수행하고 결과를 문서화한다.
